## 1. 系统简介

本系统是一套面向实验室/企业的**设备（仪器）台账与计量管理系统**，覆盖设备档案、计量记录、到期提醒、使用追踪和操作审计的完整闭环。系统采用前后端分离架构，**电脑端和手机端自动适配**：电脑浏览器打开是桌面工作台，手机浏览器打开自动切换为卡片式移动端，同一地址、同一套账号。

核心场景：

- 设备台账：建档、查询、编辑、Excel 批量导入导出
- 计量管理：计量记录留痕、证书附件存档、到期自动预警、超期自动锁定
- 消息提醒：企业微信机器人推送计量到期通知
- 合规审计：所有增删改操作自动记录审计日志，日志不可篡改、不可删除
- 移动办公：手机上查设备、看计量、查日志，支持系统返回手势逐层回退

## 2. 功能总览

| 模块 | 功能 | 桌面端 | 移动端 |
| --- | --- | --- | --- |

| 设备筛选 | 编号/名称/位置/部门/注意事项多条件筛选，服务端分页 | ✔ | ✔（搜索 + 筛选抽屉） |

| 计量预警 | 每天 9:00 自动检查，到期前 10 天企业微信提醒，超期自动锁定 | 后台任务 | 后台任务 |
| 账号管理 | 账号增删改、角色分配、重置密码 | ✔ | - |

## 3. 角色与权限

系统内置三种角色，登录后所有接口都会校验 JWT 令牌中的角色：

| 角色 | 标识 | 权限 |
| --- | --- | --- |
| 管理员 | `admin` | 全部功能：设备增删改、导入导出、计量记录维护、账号管理、企业微信设置、审计日志 |
| 普通用户 | `user` | 查看设备列表与详情、查看计量记录与证书附件、修改自己的密码 |
| 审计员 | `auditor` | 普通用户权限 + 查看审计日志（桌面端与移动端均有"审计日志"标签） |

预置账号：`admin` / `123456`（首次部署自动创建，密码已加密存储，请尽快修改）。

权限校验在后端接口层强制执行，前端界面的按钮隐藏只是体验优化，绕过界面直接调接口同样会被 403 拦截。

## 4. 技术架构

```
┌─────────────────────────────┐
│  浏览器（电脑 / 手机）        │
│  Vue 3 + Element Plus        │
│  · 桌面工作台 / 移动端双界面   │
│  · axios 统一请求 + JWT       │
└──────────────┬──────────────┘
               │ HTTP / JSON（/api 相对路径）
┌──────────────▼──────────────┐
│  Node.js + Express 5         │
│  · JWT 鉴权 / 角色校验        │
│  · 业务路由 + 审计埋点         │
│  · multer 上传（类型/大小校验）│
│  · node-cron 每日计量检查      │
│  · 托管前端静态文件（单端口）   │
└──────┬───────────────┬──────┘
       │               │
┌──────▼──────┐  ┌─────▼──────────┐
│ MySQL        │  │ 企业微信机器人  │
│ (Sequelize)  │  │ (Webhook 推送) │
└─────────────┘  └────────────────┘
```

**技术选型**

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3.5、Element Plus 2.14、Vite 8 | 桌面/移动双界面，Element Plus 中文语言包 |
| 后端 | Node.js、Express 5 | 统一 `{ code, message, data }` 返回格式 |
| 数据库 | MySQL + Sequelize 6 | 5 张表，常用查询字段已建索引 |
| 认证 | jsonwebtoken + bcryptjs | JWT 12 小时有效期，密码 bcrypt 哈希 |
| 其他 | multer（上传）、xlsx（Excel）、node-cron（定时）、axios（企业微信推送） | |

**前后端连接方式**：前端所有请求走相对路径 `/api`——开发时由 Vite 代理转发到 3000 端口；生产时由后端直接托管前端构建产物，浏览器只需访问 `http://服务器IP:3000` 一个端口。附件下载走 `/api/files/...` 鉴权接口（URL 携带 token 参数）。

## 6. 安装与部署

### 6.1 环境要求

- Windows 服务器（或其他支持 Node 的系统）
- Node.js 18 及以上
- MySQL 5.7 / 8.0，创建数据库 `device_db`

数据库连接配置在 `backend/config/db.js`（默认 `127.0.0.1`，账号 `root`）。生产环境建议将密码迁移到环境变量（见"运维指南"）。

### 6.2 安装依赖

```bash
cd beta2.0/backend && npm install
cd ../frontend/device-ui && npm install
```

### 6.3 正式运行（推荐）

```bash
cd beta2.0/backend
npm run release     # 自动构建前端并启动后端
```

启动后访问：

- 本机：`http://localhost:3000`
- 局域网其他电脑/手机：`http://服务器IP:3000`

### 6.4 开发模式（改代码热更新）

开两个窗口：

```bash
# 窗口 1：后端
cd beta2.0/backend && node app.js

# 窗口 2：前端（5173 端口，/api 自动代理到 3000）
cd beta2.0/frontend/device-ui && npm run dev
```

浏览器访问 `http://localhost:5173`。

### 6.5 启动时自动完成的事

1. 连接 MySQL 并同步表结构（含新增索引）
2. 历史空设备编号归一化为 NULL，并尝试补充编号唯一索引
3. 创建默认管理员 `admin`（若不存在）
4. 注册每日 9:00（Asia/Shanghai）的计量到期检查任务

## 7. 使用说明

### 7.1 登录

打开系统地址，输入账号密码。登录状态保存 12 小时，过期自动跳回登录页。

### 7.2 设备列表（桌面端）

- **查询**：编号/名称/注意事项/位置/部门多条件组合，结果分页展示（每页 20 条）
- **双击行**：查看设备完整详情
- **计量记录**：查看该设备的历次计量记录，可新增/编辑/删除，支持上传证书附件（pdf/jpg/png，≤10MB）
- **新增/编辑/删除**：仅管理员；设备编号全局唯一，重复会被拒绝并提示
- **导入 Excel**：仅管理员，支持 .xlsx/.xls；数据库中已存在或文件内重复的编号自动跳过，完成后提示"导入 X 条，跳过重复 X 条"
- **导出**：仅管理员，按当前筛选条件导出 Excel

### 7.3 计量状态流转

| 状态 | 含义 | 触发 |
| --- | --- | --- |
| 未校准 | 新建设备默认状态 | 建档 |
| 正常 | 最近一次计量合格 | 录入合格计量记录 |
| 即将到期 | 距下次计量 ≤ 10 天 | 每日定时检查，并推送企业微信提醒（每台设备每个日期只提醒一次） |
| 已过期 | 超过下次计量日期 | 每日定时检查，同时**自动锁定**设备 |
| 校准不合格 | 最近一次计量不合格 | 录入不合格记录，同时自动锁定 |

### 7.4 账号管理（管理员）

新增账号时可分配角色（普通用户/审计员/管理员）；编辑可修改昵称、角色、重置密码。默认 admin 账号不可删除，当前登录账号不可删除自己。

### 7.5 企业微信设置（管理员）

粘贴群机器人的完整 Webhook 地址，或只填 key（系统自动补全前缀）。可先发一条测试消息验证。配置保存后，每日计量检查发现的"即将到期"设备会自动推送到群。

### 7.6 审计日志（管理员/审计员）

- 自动记录的操作：设备（新增/修改/删除/导入/校准/超期自动锁定）、计量记录（增改删）、账号（增改删/改密码）、企业微信设置保存
- 每条日志包含：时间、操作人、模块、动作、操作对象、IP，以及**修改前后的完整数据快照**（点击行查看）
- 支持按模块/操作/操作人/关键字/日期范围筛选，分页浏览
- **日志不可修改、不可删除**：接口层不提供写入口，数据库模型层有钩子拦截

### 7.7 移动端

手机浏览器打开同一地址自动进入移动版：

- **底部导航**：设备 / 审计日志（管理员、审计员可见）/ 我的
- **设备**：顶部搜索（编号/名称/位置，输入即搜），筛选抽屉（位置/部门/计量状态/使用状态），下拉"加载更多"按页加载；点卡片看详情，详情页可进入计量记录
- **返回体验**：详情、计量记录、各抽屉弹窗都接入了系统返回手势，逐层回退，不会误退出应用
- **我的**：查看账号信息、修改密码、退出登录

## 8. 接口清单

统一约定：除文件下载外，所有 `/api` 接口要求请求头 `Authorization: Bearer <token>`；返回格式 `{ code, message, data }`，`code = 0` 为成功。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/api/auth/login` | 登录，返回用户信息与 token | 公开 |
| GET | `/api/instruments` | 设备列表（分页 + 多条件筛选） | 登录 |
| POST | `/api/instruments` | 新增设备（编号唯一校验） | 管理员 |
| PUT | `/api/instruments/:id` | 编辑设备 | 管理员 |
| DELETE | `/api/instruments/:id` | 删除设备 | 管理员 |
| PUT | `/api/instruments/:id/calibration` | 更新计量信息 | 登录 |
| POST | `/api/instruments/:id/use` `/return` | 领用 / 归还（接口已就绪，界面未开放） | 登录 |
| POST | `/api/instruments/import` | Excel 导入（跳过重复编号） | 管理员 |
| GET | `/api/instruments/export` | Excel 导出 | 管理员 |
| POST | `/api/instruments/check-calibration` | 手动触发计量检查 | 登录 |
| GET/POST/PUT/DELETE | `/api/calibration-records` | 计量记录增改删查（证书附件上传） | 查询需登录，写需管理员 |
| GET | `/api/users` 等 | 账号管理、修改密码 | 管理需管理员 |
| GET/POST | `/api/wecom/setting`、`/api/wecom/test` | 企业微信配置与测试 | 管理员 |
| GET | `/api/audit-logs` | 审计日志查询（分页 + 筛选，只读） | 管理员/审计员 |
| GET | `/api/files/*` | 附件下载（`?token=` 鉴权） | 登录 |

## 9. 数据库设计

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `user` | username（唯一）、nickname、password（bcrypt）、role(admin/user/auditor) | 账号 |
| `instrument` | code（唯一）、name、model、manufacturer、purchase_date、location、department、owner、asset_code、status(idle/in_use/repair/scrapped)、calibration_status、last/next_calibration_date、calibration_result/note、locked、lock_reason | 设备台账；name/status/calibration_status/next_calibration_date 已建索引 |
| `calibration_record` | instrument_id（索引）、instrument_code/name、result、calibration_info、calibration_date、next_calibration_date、certificate_file/name、created_by | 计量记录 |
| `setting` | key（主键）、value | 系统配置（企业微信 Webhook） |
| `audit_log` | actor_username/nickname、module、action、target_id/label、detail(JSON 快照)、ip、created_at | 审计日志，只增不删；module/action/created_at 已建索引 |

## 10. 安全机制

- **认证**：登录签发 JWT（HS256，12 小时），所有接口校验；密钥可用环境变量 `JWT_SECRET` 覆盖
- **密码**：bcrypt 哈希存储；历史明文密码在用户首次登录后自动升级为哈希
- **授权**：角色在服务端强制校验（`requireAuth` / `requireAdmin` / `requireRole`）
- **附件**：下载接口鉴权，无 token 返回 401
- **上传**：白名单扩展名 + 10MB 大小限制，临时文件自动清理
- **数据完整性**：设备编号唯一（应用层校验 + 唯一索引兜底）；审计日志模型层禁止修改/删除
- **审计**：所有写操作留痕（操作人、IP、前后快照）

## 11. 运维指南

**启动/停止**：`npm run release`（或 `node app.js`）。停止直接结束进程。若端口被占，检查是否有旧 node 进程残留（任务管理器结束 `node.exe` 后重启）。

**环境变量**：`JWT_SECRET`（JWT 密钥，生产必配）。

**数据备份建议**：每日 mysqldump，例如用 Windows 计划任务执行

```bat
mysqldump -uroot -p<密码> device_db > D:\backup\device_db_%date:~0,4%%date:~5,2%%date:~8,2%.sql
```

**证书附件备份**：`backend/uploads/certificates/` 目录随数据库一起备份。

**日志查看**：后端控制台输出（企业微信推送失败、审计写入失败等会打印错误）。

## 12. 常见问题

**Q：页面能打开但接口全部 401？**
登录已过期（token 有效期 12 小时），重新登录即可。

**Q：点击证书附件提示 401？**
登录态过期导致链接中的 token 失效，重新登录后再试。

**Q：启动后提示端口被占用（EADDRINUSE）？**
有旧的后端进程残留。任务管理器结束所有 `node.exe`，重新启动。

**Q：导入 Excel 有部分行没进来？**
这些行的设备编号与数据库或文件内已有编号重复，导入结果会提示跳过数量，审计日志中可查到具体跳过的编号（前 20 个）。

**Q：手机上看到的是什么界面由什么决定？**
由浏览器窗口宽度决定（768px 分界）。手机横屏或平板可能看到桌面版，属正常现象。

**Q：忘记 admin 密码？**
目前需在数据库中重置：将 `user` 表 admin 的 `password` 字段改为已知账号的哈希值，或联系开发人员处理。建议后续增加密码策略（见优化清单）。
